# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health()` | Returned 200 without checking MongoDB, so an unavailable database appeared ready. | Simulate a MongoDB connection failure and call `GET /health`; the starter still returns 200. | Ping MongoDB before reporting readiness; catch `PyMongoError` and return 503 with a generic error detail. |
| 2 | `EmployeeIn` fields | Employee codes, names, emails and departments lacked contract validation. | Submit `emp_code="ABC"`, an empty name/department, an invalid email, or overlong text; these should return 422. | Added the contract's patterns and length limits using Pydantic fields. |
| 3 | `EmployeeIn.joined_on` | Accepted malformed and impossible calendar dates. | Submit `2026-02-30` or `2026-7-01`; both should return 422. | Validate the exact date format and actual calendar date, preserving the stored string type. |
| 4 | `EmployeeIn` shift fields | Accepted invalid shift times and identical start/end times. | Submit `25:00`, `9:30`, or equal start/end times; expect 422. A valid overnight shift must still pass. | Added HH:MM patterns and a model validator rejecting equal shift times; retained default and overnight shifts. |
| 5 | `create_employee()` and app startup | Check-then-insert allowed concurrent requests to create duplicate employee codes; no unique index enforced the requirement. | Send 8 simultaneous creates for the same code: exactly one must return 201, the others 409, with one stored document. | Create a unique `emp_code` index at startup and catch `DuplicateKeyError` on insert instead of relying on a prior lookup. Repeated startup safely reuses the index. |
| 6 | `list_employees()` pagination | Used `page * page_size`, skipping the first page of employees. | With 25 employees, default page 1 should return the first 20, page 2 the remaining 5. | Calculate the offset as `(page - 1) * page_size`. |
| 7 | `list_employees()` filters and count | Counted the entire collection even when filtering by department; an explicit empty filter was ignored. | Filter by a department with fewer employees, an unknown department, or an empty string; total must match that exact filter. | Use the same query for count and listing; apply any supplied department, including an empty string. |
| 8 | `list_employees()` sorting | Did not sort by employee code before pagination. | Insert employees in reverse code order and request consecutive pages; results must be ascending without gaps or overlaps. | Sort by `emp_code` ascending in MongoDB before skip/limit. |
| 9 | `list_employees()` query parameters | Accepted out-of-range page and page-size values. | Request page 0, a negative page, page_size 0, or page_size 101; expect 422. | Add FastAPI query constraints: page >= 1 and page_size between 1 and 100. |
| 10 | `create_employee()` creation time | Used a naive local datetime, which PyMongo treats as UTC, shifting the stored instant on non-UTC hosts. | Freeze the server clock and create an employee; the stored time must represent that exact UTC instant with whole-second precision. | Use timezone-aware UTC now and truncate microseconds before storing. |
| 11 | Employee create/list responses | Returned datetimes as strings rather than integer epoch milliseconds. | Check both responses and a seeded naive UTC datetime; `created_at` must be an integer with the correct instant regardless of the host timezone. | Share an employee serializer that converts datetime to integer milliseconds, treats naive database datetimes as UTC, omits `_id`, and leaves stored BSON dates unchanged. |
| 12 | `PunchInIn.status` | Allowed arbitrary status strings, including ABSENT and LEAVE, for punch-in. | Send ABSENT, LEAVE, an unknown status, or null; expect 422. | Restrict status to PRESENT, WFH and ON_DUTY, retaining the PRESENT default. |
| 13 | `PunchInIn.punched_at` and `punch_in()` | Coerced non-integer timestamps, accepted null/out-of-range values, and treated zero as omitted. | Send seconds, a numeric string, float, boolean, null, zero, or a value outside the contract bounds; expect 422 before database access. | Use a strict integer field with inclusive millisecond bounds; only omission generates the current timestamp. Remove the truthiness fallback. |
| 14 | `punch_in()` employee lookup | Dereferenced a missing employee, producing a server error. | Punch in with an unknown employee code; expect 404 and no attendance write. | Check for a missing employee immediately after lookup and raise HTTPException 404. |
